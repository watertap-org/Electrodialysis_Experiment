``k_stage_single_pass.py``
==========================

Location
--------

``src/electrodialysis_experiment/processes/k_stage_single_pass.py``

Purpose
-------

``k_stage_single_pass.py`` generalizes the single-stage wrapper to an arbitrary
number of electrodialysis stages connected in series. It is the process-layer
module used when one electrodialysis stack is not enough and stage-specific
behavior must be represented explicitly.

The central class is ``KStageSinglePass`` (implemented as
``KStageSinglePassData`` through ``declare_process_block_class``).

High-level design
-----------------

The module builds one shared process flowsheet and then creates a stage-indexed
block of electrodialysis stacks:

- one shared ``Feed`` block,
- one shared ``Separator`` block,
- two shared pumps,
- a stage set ``fs.stage_set``,
- one ``ED_base`` instance per stage under ``fs.EDstack[stage].unit``, and
- shared terminal ``Product`` blocks for the final product and disposal streams.

This design keeps upstream and downstream process structure simple while letting
the electrodialysis behavior vary by stage.

Configuration model
-------------------

The wrapper is driven by ``KStageSinglePassConfig``. It supports:

- a default ``ed_stack`` definition,
- optional stage-specific overrides in ``ed_stacks``, and
- ``num_stages`` to control the length of the train.

The helper methods ``_stage_indices()``, ``_normalize_stage_list(...)``, and
``_get_stage_config(stage_num)`` exist to make stage-aware updates and lookups
predictable.

Key difference from the one-stage wrapper
-----------------------------------------

``OneStageSinglePass`` assumes one stack and one set of fixed process inputs.
``KStageSinglePass`` adds:

- one stack model per stage,
- stage-wise voltage and current-density expressions,
- stage-wise experimental-voltage and open-circuit-voltage variables,
- stage-specific parameter fixing, and
- inter-stage arcs that pass outlet states from one stage into the next.

This is the main process abstraction for two-stage and larger staged systems.

Important public methods
------------------------

``from_yaml(path)``
  Build the k-stage wrapper from YAML.

``initialize_process(...)``
  Apply the feed state, initialize the units and all stages in order, propagate
  inter-stage states, and optionally solve the full flowsheet.

``update_cation_cem_transport_number(..., stage_list=...)``
  Fix cation transport-number values for selected stages.

``fix_steady_constant_current(..., stage_list=...)``
  Fix or constrain the applied current for selected stages, depending on whether
  the stage runs in constant-current or constant-voltage mode.

``update_var_values(...)``
  Apply non-stage-specific variable fixes.

``update_stg_dep_var_values(stage_num, updates)``
  Apply stage-specific variable fixes to one or more selected stages.

``display_selected_model_metrics(...)``
  Print selected process metrics across the staged flowsheet.

``plot_lengthwise_profile(...)``
  Plot spatial profiles from selected stage units.

Initialization pattern
----------------------

The initialization sequence is similar to the one-stage model but includes stage
ordering:

1. Fix the feed state.
2. Initialize feed, separator, and pumps.
3. Initialize the first ED stage.
4. Propagate outlet states to the next stage.
5. Initialize each downstream stage in order.
6. Propagate the final stage outlets to the product and disposal blocks.
7. Initialize the terminal blocks.
8. Solve the full coupled flowsheet.

This sequential pattern reduces the difficulty of solving the full staged model
from a cold start.

When to edit this file
----------------------

Edit ``k_stage_single_pass.py`` when the change is about process topology or
stage-aware behavior, for example:

- adding or changing inter-stage connections,
- supporting new stage-specific update rules,
- introducing stage-wise operating constraints, or
- changing how staged metrics are reported.

Do not edit this file for stack-level physics changes that should apply to every
stage identically. Those belong in ``base.py``.
